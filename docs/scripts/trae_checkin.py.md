# Trae 每日签到与积分查询

- 管理状态：`待检查`（与本地脚本管理一致：待检查 / 已检查 / 上架）
- 脚本路径：`scripts/trae_checkin.py`
- 青龙命令：`python3 scripts/trae_checkin.py`
- 建议 Cron：`7,23,37 * * * *`
- 发布哈希：`f63865bbac4dc41df972bf44f285801dc58a00c111e305211ed756b29f2d3b8e`
- 许可证：`MIT`

## 脚本功能

- 每日签到：先查状态，按需领取积分并以同一设备复查确认；当日已核验完成的账号零请求复用本地状态。
- 独立积分查询：TRAE_TASK=credits 或 credits 命令只读查询；保留 entitlement 到 ide_user_ent_usage 的备用链，兼容用量汇总和权益包余额计算。
- 同账号网页会话换令牌、长效 sessionid 续期和显式桌面凭据回退，保留百分号编码、真实设备绑定及配套指纹。
- 桌面令牌自动续期、纯标准库 P-256 设备签名和客户端产品线回退；轮换令牌以 0600 权限原子缓存，兼容 JWT 标准及自定义到期声明。
- 显式凭据文件兼容：icubeAuth、storagePath、authPath 和 TRAE_AUTH_DIR；可选 cryptography 解密，显式存储可提供同设备证明，不扫描客户端目录。
- 显式 login 交互授权：本地回调和隐藏粘贴表单、超时控制、续期接口核验与安全凭据保存；无外部应用或其他仓库依赖。
- 每行多账号独立执行、旧参数兼容、指定账号筛选、默认全签与按小时轮签、北京时间早窗、限流冷却、可选熔断及错峰。
- 只使用官方成功证据判断签到及余额；公开昵称、用户名和 UID 可见，重复配置和失效凭据单独统计，任一账号未完成整体非零退出。
- 完全断网预演；时间轴、编号阶段、各账号和全任务统计、完成时间、通知状态及唯一单行 TASK_SUMMARY 结构化汇总。
- 按通知名单及全局开关调用青龙 notify.py 或 sendNotify.js，保留企业微信与 PushPlus 及其旧变量别名；预演提交脱敏摘要且拦截通知器网络、子进程和文件写入。

## 环境变量与参数

先配置必选参数再运行；缺少任一必选参数时任务会失败。敏感值不得写入脚本、订阅地址或公开日志。

### 必选参数

### `TRAE_ACCOUNTS`

- 必填：是
- 敏感：是
- 获取或设置：规范账号变量。每个非空行填写一个账号的 JSON 对象。在本人已登录的官方客户端登录响应中取得 accessToken、refreshToken；从本人 storage.json 的 iCubeAuthInfo://icube-dc:<数字> 键取得真实 deviceId。新版续期的 deviceKeyPem、devicePubPem、machineId 必须来自同一设备，可从该设备的加密存储安全导出；不得生成或借用设备号。网页凭据在本人登录 https://www.trae.cn 后，通过浏览器开发者工具→应用→Cookie 取得 X-Cloudide-Session 和 sessionid 的单个 Value，分别填 session、sessionid，保留百分号编码。也可先在本机配置真实 TRAE_DEVICE_ID 后执行 python3 candidate.py login，按本地入口完成授权，再显式使用生成的 authPath。无需在青龙安装客户端或克隆其他仓库。
- 填写格式：每行一个 JSON 对象：deviceId 加 accessToken 或 refreshToken，或 deviceId 加 session 和/或 sessionid。同账号可合并桌面令牌与网页凭据以提供回退。可选 uid、name、expiresAt、deviceKeyPem、devicePubPem、machineId、fingerprint；真实设备号为 12 至 20 位数字字符串。兼容旧 JSON 数组及 token/access_token、refresh_token、realDeviceId/device_id、claimDeviceId（最高优先级）、account_name/screenName、expires_at、userId/user_id 别名。不使用 & 或 @ 分隔账号。可显式提供 icubeAuth、storagePath、authPath，仅读取本人配置的文件；预演须改用占位明文凭据。

### 可选参数

### `TRAE_ACCESS_TOKEN`

- 必填：否
- 敏感：是
- 获取或设置：可选旧变量兼容输入；从本人官方客户端登录响应取得访问令牌，建议合并至 TRAE_ACCOUNTS。
- 填写格式：第 1 个账号的访问令牌原值；同序号的设备号和令牌必须属于同一账号。

### `TRAE_REFRESH_TOKEN`

## 多账号

TRAE_ACCOUNTS 每个非空行一个账号 JSON 对象，同账号令牌、网页会话、真实设备号及设备证明放在同一对象中；不按 & 或 @ 分割。保留旧 JSON 数组和明确列出的旧变量输入。账号逐个独立处理，任一账号失败、未完成或配置错误时整体非零退出；仅官方成功响应的公开 UID 用于重复配置识别。

## 副作用与风险

- 正式 checkin 动作在官方状态确认未签到且开放时领取每日签到积分。
- 正式令牌续期可能轮换服务端 refreshToken；网页长效 Cookie 续期可能更新服务端会话，并将新凭据写入权限 0600 的本地缓存。
- 正式签到写入本地当天已核验状态及限流冷却记录。
- 显式 login 动作建立官方授权会话，监听本机回调并在核验后写入权限 0600 的本人授权文件。
- 通知策略选中且启用时，通过本人配置的青龙、企业微信或 PushPlus 渠道发送脱敏摘要；预演禁止网络投递及通知器文件写入。
