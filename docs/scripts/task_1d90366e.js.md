## 脚本功能

- 使用 OpenLayer Bearer Token 查询用户信息并完成每日签到。
- 展示官方返回的 X 名称、X 用户名、钱包地址、积分、倍数、连续签到次数与宠物信息等非敏感字段。
- 识别签到成功与今日已签到；支持每行一个 Token 多账号，兼容 OPENLAYER_TOKEN 与上游 BEARERS/JSON 数组。
- 可选自定义 API 根地址与请求超时。
- 按青龙全局开关与脚本名单发送脱敏通知，通知失败保留业务退出码。
- 完全断网预演：校验 Token 格式、模拟阶段与通知摘要，不发起业务或通知网络请求。
- 提供中文时间轴日志、编号阶段、耗时、逐账号与全局统计，以及唯一单行 TASK_SUMMARY JSON。

## 环境变量与参数

先配置必选参数再运行；缺少任一必选参数时任务会失败。敏感值不得写入脚本、订阅地址或公开日志。

### 必选参数

### `OPENLAYER_BEARER`

- 必填：是
- 敏感：是
- 获取或设置：打开 OpenLayer 浏览器扩展并登录本人账号，右键页面选择检查，在 Console 执行 console.log(localStorage.getItem('_open_layer_token_'))，复制返回的 Bearer Token。勿使用他人 Token，勿写入公开仓库、日志或通知。
- 填写格式：每个非空行一个账号 Token。可不含 Bearer 前缀（脚本会自动补全）。可选「备注|token」，只在首个竖线处拆分。不使用 & 或 @ 分隔账号。

### 可选参数

### `OPENLAYER_TOKEN`

- 必填：否
- 敏感：是
- 获取或设置：兼容别名：仅当未设置 OPENLAYER_BEARER 时读取；获取方式与 OPENLAYER_BEARER 相同。
- 填写格式：与 OPENLAYER_BEARER 相同；每行一个 Token。

### `BEARERS`

- 必填：否
- 敏感：是
- 获取或设置：兼容上游 bearers.json：仅当 OPENLAYER_BEARER 与 OPENLAYER_TOKEN 皆为空时读取；可为换行多 Token，或 JSON 字符串数组。
- 填写格式：每行一个 Token，或形如 ["token1","token2"] 的 JSON 数组文本。

### `OPENLAYER_DRY_RUN`

- 必填：否
- 敏感：否
- 获取或设置：需要断网验证配置时手动设置；正式执行时删除或设为 0。
- 填写格式：1、true、yes、on 表示完全断网预演；其他值或未设置表示正式执行。预演不访问 OpenLayer、不签到、不投递真实通知。

### `OPENLAYER_TIMEOUT_MS`

- 必填：否
- 敏感：否
- 获取或设置：需要调整单次 HTTP 超时时间时手动设置。
- 填写格式：1000 至 60000 的整数毫秒；缺省或非法值使用 15000。

### `OPENLAYER_BASE_URL`

- 必填：否
- 敏感：否
- 获取或设置：官方 API 根地址变更时手动覆盖；一般可留空。
- 填写格式：HTTPS 根地址，不要末尾斜杠；缺省为 https://us-central1-openoracle-de73b.cloudfunctions.net

### `QINGLONG_NOTIFY`

- 必填：否
- 敏感：否
- 获取或设置：青龙通知总开关；未设置时仅上架脚本默认推送。显式设置后覆盖脚本选择策略。
- 填写格式：留空按上架状态；1、true、yes、on 全部开启；0、false、no、off 全部关闭。

### `QINGLONG_NOTIFY_SCRIPTS`

- 必填：否
- 敏感：否
- 获取或设置：在青龙通知名单中填入 1d90366e2210d9c6、实际脚本文件名或 scripts 相对路径；未设置时默认对本任务发送通知。
- 填写格式：逗号、分号、空白或换行分隔的选择器；支持 * 与 ? 通配；* 表示全部；显式空值关闭全部青龙通知。

### `QINGLONG_NOTIFY_DIR`

- 必填：否
- 敏感：否
- 获取或设置：青龙通知工具不在默认目录时，填写本机 sendNotify.js 或 notify.py 所在目录。
- 填写格式：本地目录路径。依次尝试指定目录与 /ql/data/scripts、/ql/scripts 下的 sendNotify.js，再尝试 notify.py；通知失败只记录脱敏状态。

## 多账号

OPENLAYER_BEARER（或兼容 OPENLAYER_TOKEN / BEARERS）每个非空行一个账号 Token；可选备注仅按第一个竖线分割。账号逐个独立查询用户信息与签到统计，任一账号失败则整体非零退出，其余账号继续执行。
